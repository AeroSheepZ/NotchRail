# 0002. 外接平直显示器采用动态菜单碰撞计算与按需借调悬浮展开

### 背景
macOS 外接显示器均为无硬件刘海的平直屏幕。以往方案在外接屏正中央硬编码一个 160pt 宽的假想刘海（Virtual Notch），导致图标只要跨过屏幕中央就被误判为溢出，造成无中生有的虚假展示；同时在屏幕中央常驻一个纯黑假胶囊，严重破坏原生菜单栏美感，遮挡底层窗口。但若彻底禁用外接屏，当用户运行 Xcode、Photoshop 等菜单超长的重型软件时，原生被系统吞噬挤压的三方图标又无法被救回，且合盖模式（Clamshell）下软件将完全瘫痪。

### 决议
1. **废除假想刘海，实施真实物理碰撞判定**：平直外接屏 `physicalNotchRect` 设为 `.zero`。通过异步事件流捕获前台应用菜单栏的右边界（`AppMenuMaxX`），当且仅当状态栏项左边界侵入菜单碰撞区（`item.minX < AppMenuMaxX + 12pt`）时才判定为溢出。
2. **常态 0 像素绝对隐形**：外接屏平时完全不显示任何紧凑胶囊（`alpha = 0`，`ignoresMouseEvents = true`），彻底消除假刘海视觉污染。
3. **视口借调与中央碰顶展开**：全局单例 `IslandPanel` 视口常态下始终守护在 MacBook 物理刘海屏；仅当外接屏检测到真实溢出且光标在屏幕顶部中央（240pt × 4pt 热区）停留超过 120ms 时，Panel 原子借调迁移至外接屏平滑滑出展开；收起后无感归位回 MacBook 刘海屏。
4. **即时收起与平直贴顶**：点击岛外空白处立即收起（Dismiss on Click Outside）；外接屏展开时顶部左右耳翼半径置为 0（`topEarRadius = 0`），呈现无假刘海的原生悬浮托轨（Floating Shelf）。

### 理由与权衡
此方案在保留完整多屏兼容性与合盖能力的前提下，消除了假刘海的物理荒谬性与视觉侵入，达成了原生人机工效与物理真实性的最佳平衡。

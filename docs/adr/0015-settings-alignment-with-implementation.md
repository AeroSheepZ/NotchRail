# 0015. 设置项与实现对齐：删除名不副实的选项

> **状态：部分被 ADR 0016 取代** —— **决议 4（紧凑胶囊点击维持「仅展开」）已作废**，其技术前提（容器手势用了 `simultaneousGesture`，「改切换会劫持图标交互」）不成立，改用 `.onTapGesture` 即可让图标 `Button` 优先。胶囊点击现为**展开/收起切换**，详见 [ADR 0016](0016-capsule-tap-toggles-expand-collapse.md)。**决议 1、2、3、5 继续有效，正文保持原样不改写。**
>
> 本 ADR 收束 v0.0.10 排查中发现的三处「设置项承诺 ≠ 代码实际」。三者同源于一类缺陷：**把一个不可选项、或一个文案未兑现的行为，做成了用户可切换的开关**。

### 背景

排查起因是「设置面板好多设置项失灵」。核对后的准确表述是：**值改得动、也存得住，但功能不是文案说的那个**。逐项对到代码消费者后，确认常规分区共三处不一致，且**都不是绑定链断裂** —— 数据层（`PreferenceStore` 唯一实例、发布式落盘、偏好变更广播）完好无损：

1. **多显示器策略三档实际只有两档。** `IslandWindowCoordinator.allowsPanel` 只放行 `.followFocusedScreen`，故第三档（原意「外接屏彻底禁用」）与 `.mainScreenOnly` 的可观察行为完全相同；更糟的是 `ScreenManager.effectiveGeometry(for:)` 把该档**并进了 `.followFocusedScreen` 分支** —— 同一个枚举、两处相反口径。用户切到该档，看到的是「什么都没变」。
2. **「点击图标后自动收起」被做成了可关闭的开关，但收起是平台不变式。** 灵动岛视口层级高于原生菜单窗口，不收起则刚弹出的菜单被压住；代码自身在收起处已注明「收起是必需的」。关掉该开关，用户期待「灵动岛保持展开」，实际得到「原生菜单被遮挡」，且无从从开关文案得知。
3. **「无遮挡图标时自动隐藏紧凑胶囊」的文案与实现语义不符。** 实现为「0 溢出期间整体隐退**并静默**」—— 面板隐形、命中区归零、顶边缘热区早退，托盘菜单这条显式唤出路径亦同样放行；文案却只承诺「隐藏胶囊」。用户据此以为它只是个外观开关。

### 决议

1. **删除多显示器策略第三档，收敛为两档。** 保留「多屏独立多轨」与「仅主显示器」。历史落盘值在解码时**显式迁移**为「仅主显示器」（与其真实行为一致）；**不得**因编码值查不到而静默落回默认档 —— 那会把曾选该档的用户悄悄切换成多屏独立模式，属语义漂移而非兼容。
2. **删除「点击图标后自动收起」偏好项。** 派发成功后**恒定原子收起**，不提供关闭入口。
3. **固化「无遮挡时静默」语义并据实改写文案。** 该偏好为真且当前屏 0 溢出时，灵动岛整体隐退且**任何唤出形式一律不生效**（悬停、点击、托盘菜单命令）；该档**优先于**灵动岛打开方式，让位关系须写进设置项说明，不得留给用户推断。
4. **紧凑胶囊的点击语义维持「仅展开」，不引入展开/收起切换。** 展开态的收起由「点击灵动岛以外区域」或「点击任一图标后自动收起」承担；**不得**为兑现文案而把点击改成切换 —— 该手势与图标、设置齿轮的点击同层并发，改成切换会连带劫持这些交互。文案须写清实际收起方式。
5. **开机自启动的注册结果必须可见。** 该偏好只是系统侧注册状态的**镜像**；注册失败、待批准、偏好与系统不一致三种情形一律在设置面板如实呈现，**不得**静默回写。

### 理由与权衡

**为何删选项而不是改实现的判据**：区分点在于「**哪一侧才是真实意图**」。

- 第 1 处：两档行为等价，保留三档等于给用户一个**假选择**；把第三档重定义成新行为属于新增功能，不在「对齐」范围内。
- 第 2 处：收起由平台层级关系决定，不取决于用户意愿 —— 把不变量的定义权交给用户，得到的不是自由度，而是一个**必然被违反的承诺**。
- 第 3 处方向相反：这处是**实现正确、文案不准**（该档的本意就是「没有溢出就不该出现」），故改文案、不动实现。

**三处同查却给出两种相反的修法**，正是这条判据在工作 —— 若统一按「删选项」或统一按「改文案」处理，都会把其中一处改错。

**代价**：

1. 用户可见的选项变少（少一个开关、少一档策略）。曾选第三档的用户被迁移到「仅主显示器」，其可观察行为不变。
2. 一律收起使得「连续点第二个图标」需要重新展开。这是保证原生菜单可见的必要代价。
3. 第 3 处按「完全静默」固化后，0 溢出期间用户没有任何唤出路径 —— 有意为之：该档存在的意义就是「不出现」。
4. 第 4 处选择改文案而非改手势，意味着文案必须把收起方式写清楚，而不是把成本转嫁给图标交互。

### 影响

- `ExternalDisplayMode` 收敛为两值，偏好解码承担历史值迁移；`ScreenManager.effectiveGeometry(for:)` 的两处相反口径随之消失。
- 偏好模型移除「点击图标后自动收起」字段，派发后的收起不再读取偏好；设置面板移除对应开关。
- 「无遮挡时静默」的行为不变，仅文案与托盘菜单命令的可用性随之对齐（静默态下禁用展开命令并给出原因）。
- 开机自启动管理器的切换接口由「无返回值」改为「回报结果」，设置面板据此呈现。
- `CONTEXT.md` 新增 `SilencedByNoOverflow` 词条固化决议 3 的语义；结构与字段一律以 `docs/DOMAIN_MODEL.md` 为准，本文不复述。
- `docs/SPEC.md` 为历史归档（`AGENTS.md` §0 归属矩阵第 7 行），**不追改**。
- 测试须覆盖决议 1 的迁移方向：历史编码值必须落到「仅主显示器」，**不得**落到默认档。

# 0017. 状态栏单前台活动屏独占公理与交互驱动活动权移交（Focus Handoff）

> **状态：现行** —— 本 ADR **修正 ADR 0013 决议 1 与决议 4**（修正关于「非活动屏无需移交焦点即可通过区域级合成独立自采位图并原位派发点击」的前提与假设）。ADR 0013 关于废除跨屏图元共享层、图元键纳入 `displayID` 的决议继续有效。
>
> **实现状态：已落地（v0.0.11）** —— 决议已全面落地闭环。Focus Handoff 服务与零抢焦焦点还原机制已就位，按屏独立自治与单前台活动屏独占公理已闭环。

### 背景

在 v0.0.10 及 ADR 0013 的推演中，曾设立一项假设：「非活动屏的状态项被 WindowServer 真实绘制，区域级合成截图可独立采出单项位图，非活动屏可在不改变当前活动屏的情况下原位派发点击」。

2026-09-16 在真实双屏硬件环境（macOS 15/26，内建刘海屏 2x + 外接平直屏 1x，前后互换焦点两轮）实测，四维探针**全面证伪了该假设**：

**探针一 · 事件派发物理落点差分**
- 向非活动屏上的状态项（例如外接屏上的 Clash，`win=70258`，归属于控制中心宿主）派发原生按下事件：
  - 新增的菜单窗口（`win=87707`，348×277）**强制弹在活动屏（内建刘海屏）的刘海右侧**；外接屏原位没有任何弹窗；
  - 若活动屏无同名状态项或处于无对应上下文桌面，事件直接被系统**静默丢弃，零新增窗口**。
  - ⇒ **macOS 绝不支持在非活动屏原位弹出状态栏项菜单。**

**探针二 · 逐窗截图 API 返回全透明**
- `Bridging.captureWindow` 对非活动屏的所有窗口**恒定返回全透明位图**（有效像素为 0）。WindowServer 在非活动屏上直接切断了单窗口光栅化缓冲区读取。

**探针三 · 区域级合成截取极其不稳定**
- 使用 `Bridging.captureRegion` 截取非活动屏菜单栏条带：实测在非活动屏处于非前台 Space 或特定状态时，WindowServer 在该帧缓冲中**完全不合成状态栏项**，截出的仅为桌面背景壁纸，14 项单项几何 Crop **全部为全透明失败**。
- ⇒ **非活动屏的位图光栅化非稳定常驻，绝不可当作可靠图元供给来源。**

**探针四 · 辅助功能条目池（AXExtrasMenuBar）绝对独占**
- `MenuBarAXResolver` 从系统获取的有效条目数：**活动屏拥有全部有效条目（实测 13 项），非活动屏有效条目数恒为 0（全部为 0×0 的退化条目）**。将焦点移至另一屏后，两屏分布瞬间整体互换。

### 决议

1. **macOS 状态栏单前台活动屏独占公理（Active Menu Bar Monopoly）**：
   - macOS 状态栏系统服务（WindowServer、控制中心、AXExtrasMenuBar）在系统底层是严格单前台独占的。
   - **严禁任何绕过焦点试图在非活动屏原位派发点击、强行提取未光栅化图元的实现尝试**。
2. **交互驱动的活动权无感移交（Focus Handoff）**：
   - 灵动岛的交互（碰顶唤醒、悬停展开、胶囊点击）表明了用户当前的物理交互重心。
   - 在用户与某屏的灵动岛发生交互时，系统通过焦点流转机制（`FocusHandoff`）将该屏幕确立为当前活动菜单栏屏（Active Menu Bar Display）；
   - 该移交必须是用户显式交互行为驱动的确定性转移，严禁程序后台猜测性争抢。
3. **活动屏生命周期下的原生能力闭环**：
   - 一旦目标屏幕成为活动菜单栏屏：
     1. 该屏的状态项窗口获得 WindowServer 真实光栅化支持，逐窗截图与区域裁剪 100% 可达；
     2. `AXExtrasMenuBar` 空间映射 100% 覆盖该屏所有三方项；
     3. 合成点击事件 100% 原位在该屏弹出原生下拉菜单，杜绝跨屏误弹与静默丢弃。

### 理由与权衡

**为何必须接受「单前台独占」而不是继续寻找黑魔法**：
探针证据表明，状态栏事件路由与光栅化管道在 WindowServer 和控制中心内部深层绑定了 `kCGSActiveMenuBarDisplay` 状态。试图向非活动屏窗口派发事件，本质是在向一个处于休眠/去激活态的宿主对象投递消息，其结果要么是跨屏误弹（被活动屏劫持），要么是静默丢失。承认平台客观规律、顺应系统生命周期（在交互时完成活动权移交），是唯一稳定可靠且符合原生 macOS 体验的架构路径。

**与 ADR 0013 的关系**：
ADR 0013 确立的「废除跨屏共享层、图元键包含 `displayID`、每屏只消费本屏位图」等核心结论完全正确并继续生效；ADR 0013 遗留的未决项「非活动屏原位派发是否成立」已由本次实测彻底证伪并由本文盖棺定论。

### 影响

- 修正 ADR 0013 决议 1 与 4 中关于非活动屏可直接取图和原位派发的表述；
- `AGENTS.md` §2.1 与 §3.1 固化「单前台活动屏独占公理」，将 Focus Handoff 确立为多屏交互的前置不变量；
- `CONTEXT.md` 补充 `FocusHandoff` 术语，强化 `ActiveMenuBarDisplay` 的单前台独占内涵；
- `docs/DOMAIN_MODEL.md` §6 矩阵登记本 ADR；
- v0.0.11 的实现规划明确为：基于 Focus Handoff 机制实现每屏自采与原位点击，彻底拆除 `appAssetVault` 与跨屏共享补丁。

# 0014. 排序偏好默认按屏独立，多屏共用须显式选择

> **状态：现行** —— 本 ADR 确立「**跨屏共享一律默认关闭、且只能由用户显式开启**」在偏好层的落地方式，与 [ADR 0013](0013-per-display-icon-capture.md) 在数据层的同类决议互为表里。
>
> **实现状态：待办（v0.0.11）** —— 决议已生效并落到 `AGENTS.md` §2.0 与 `CONTEXT.md`，但**代码尚未落地**（`customItemOrder` 现仍为全局单数组；明细见下文「影响」，排期见 `docs/DEVELOPMENT_PLAN.md` 的 v0.0.11 行）。读到与决议不符的代码时，以本 ADR 为准则、以代码为现状。

### 背景

`UserPreferences.customItemOrder` 是**全局单一数组**，被所有屏幕共用：用户在任意一块屏的展开态灵动岛里拖拽重排图标，其结果是**所有屏幕的排列一并改变**。

这不是一处缺陷，而是一处**未经用户选择的跨屏数据共享**。它的问题不在「共享本身」，而在**共享被默认为真且无退出路径**：

1. 它从无任何交互向用户表明「你这次拖拽会同时改动别的屏」；
2. 用户在 A 屏为「屏幕上这一块位置」建立的排列直觉，被静默投射到 B 屏 —— 而两块屏的槽位分布本就不同（一块有物理刘海、一块没有，被挤占的项集合不同）；
3. 与多屏双轨制（[ADR 0009](0009-multi-display-panel-registry.md)、[ADR 0013](0013-per-display-icon-capture.md)）的方向相反：双轨制要求「每块屏拥有完全独立的数据空间」，而排序是唯一一处**默认跨屏**的偏好数据。

同时必须承认另一半事实：**确实存在希望「所有屏的图标排列保持一致」的用户**。一刀切禁掉共享，等于替这类用户做决定，是把一种强制替换成另一种强制。

### 决议

1. **排序偏好默认按屏独立**：每块屏拥有自己的排列，在任一块屏上拖拽重排**不得改变**其它屏的排列。
2. **多屏共用一份排序是用户可选项，且必须显式开启**：用户可在设置中主动切换到「所有屏幕共用同一份排序」；切换后排序在多屏间同步。共享是**用户的选择**，不是默认状态。
3. **存储结构由单一数组改为按屏分区**，分区键为该屏的**稳定标识**；默认读写本屏分区，共享模式下所有屏读写同一分区。
4. **升级不得丢弃既有习惯**：既有用户的单一排序在升级后作为**每块屏的初始排序**铺开至各屏分区。
5. **屏幕稳定标识的选取须在实现阶段定案**：`displayID` 在插拔显示器、更换接口后不保证稳定，须评估是否改以显示器 UUID 派生持久键。该决定不仅影响排序，也影响**一切按屏持久化的偏好**，故不在此 ADR 内预设。

### 理由与权衡

**为何默认必须是「不共享」**：跨屏共享的唯一正当来源是**用户的明确意图**。当一个共享行为既不被用户要求、也不向用户表明自身存在时，它在用户侧呈现为**不可解释的行为**（「我没动过那块屏，它怎么变了」）。双轨制选择「默认隔离」，正是为了让「跨屏影响」这件事**永远需要有人明确要求才会发生**。

**为何不干脆取消共享能力**：共享有真实的需求场景（外接屏与内建屏的项集合高度重合时，维护两套排列是纯粹的重复劳动）。直接把选项删掉，是用一种不可选择的强制替代另一种不可选择的强制 —— 与本次修正的初衷相悖。正确的形态是**把默认值与可选项分开**：默认可预期，可选项可达。

**与 ADR 0013 的关系**：0013 处理的是**图元数据**（位图不该跨屏借用，因为借用会让一块屏的正确性取决于另一块屏的历史），本 ADR 处理的是**用户偏好数据**（排列默认不跨屏，因为跨屏影响必须经用户同意）。两者的分野在于**「这块屏的内容是否正确」与「用户想怎么摆」是两类不同的事实**：前者必须严格按屏隔离、没有商量余地；后者属于用户意志，可以跨屏，但**必须由用户说出来**。这个区别是本 ADR 存在的理由 —— 若不分野，很容易把「禁止跨屏借用」误推成「禁止一切跨屏一致性」，从而把可选项也一并砍掉。

**代价**：

1. 用户若确实想要所有屏一致，需要主动去设置里切换一次，「开箱即一致」不再成立。这是把便利性换成可预期性，属有意取舍。
2. 按屏分区需要一块屏的稳定标识，而该标识的稳定性尚未定案（见决议 5）。在定案前，实现须以「**不可靠时宁可退回按屏独立、绝不静默跨屏合并**」为准则，避免为了稳定性而重新引入默共享。

### 影响

- `UserPreferences.customItemOrder` 的字段语义由「全局唯一排序」变为「**某一作用域下的排序**」，新增作用域偏好项；两者结构见 `docs/DOMAIN_MODEL.md`；
- `MenuBarSnapshot` 与 `OverflowCalculator` 消费排序时须按本屏作用域取用，不得直接读全局字段；
- `CONTEXT.md` 的 `CustomItemOrder` 词条须补入作用域语义；
- 与 [ADR 0013](0013-per-display-icon-capture.md) 同属 v0.0.10 的多屏隔离范畴；
- **未决项**：屏幕稳定标识的选取（见决议 5），须在实现阶段定案并回填本 ADR 或另立 ADR。

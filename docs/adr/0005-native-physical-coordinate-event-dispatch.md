# 0005. 原生物理坐标事件派发与锚点策略

### 背景
用户点击灵动岛内的溢出图标后，原生菜单的弹出锚点存在两种技术路径：
- 路径 A：向窗口真实物理坐标派发原生事件，菜单在右上角原生位置弹出；
- 路径 B：在点击瞬间临时将三方窗口移动到灵动岛下方，迫使菜单就地弹出（类似某些三方工具早期的做法）。

在 macOS 14/15 强化沙盒、SIP 与 Hardened Runtime 环境下，强行篡改三方窗口 Frame 存在极高副作用，易引发菜单栏排版重排、跨屏闪烁乃至宿主进程异常崩溃。

### 决议
坚持 **100% 原生物理坐标事件派发（NativeMenuAnchor）**。通过 `MenuBarItemClicker` 利用 `CGEvent.postToPid` 直接按真实窗口中心合成点击事件，并在派发后自动收回灵动岛（或触发触觉反馈）。

### 理由与权衡
此举彻底规避了 Hook 私有 API 与移动窗口的崩溃风险，保持零侵入、纯本地事件流的最高稳定性；辅以点击后灵动岛自动收起动效，用户视线与操作能够自然引导至展开的原生菜单上。

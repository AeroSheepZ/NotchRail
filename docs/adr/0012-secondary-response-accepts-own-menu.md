# 0012. 辅助点击响应判定接受本进程菜单（修正 ADR 0011 决议 4）

> **状态：现行** —— 本 ADR 修正 [ADR 0011](0011-secondary-click-session-event-routing.md) **决议 4** 的 owner 过滤子句：删除其中的「**非本进程**」一项。ADR 0011 的决议 1、2、3、5、6 与决议 4 的其余部分继续有效。

### 背景

ADR 0011 决议 4 把响应判据定义成三条合取：**新的菜单层窗口** ∧ **owner 非菜单栏宿主** ∧ **owner 非本进程**。第三条建立在一个从未取证的假设上 —— 「NotchRail 自己的窗口必然是噪声」。该假设对**自有灵动岛视口**成立（`IslandPanel.level` 为 `.screenSaver`，不在菜单层），但对 **NotchRail 自己的状态项**恰好相反：自身状态项的菜单（`StatusItemManager` 持有的 `NSMenu`）由本进程弹出，同样落在 `kCGPopUpMenuWindowLevel`。

v0.0.10 真机反馈（2026-09-16）：在灵动岛内右键**被刘海挤占的 NotchRail 自身溢出图标**，其原生托盘菜单**确实弹出**，但灵动岛保持展开并 Shake，未收起 —— 判定给出的反馈与用户眼前真实发生的结果直接矛盾。

真机探针（本机 macOS 26，`NSStatusItem` + `NSMenu` 连续弹出 3 次，每轮在弹出中与关闭后各采样一次菜单层窗口表）：

| 轮次 | 本进程菜单层窗口（弹出中） | 该窗口关闭后 |
| :--- | :--- | :--- |
| 第 1 次 | `83888`（新增） | 仍留在枚举结果中 |
| 第 2 次 | `83888`、`83889`（新增 `83889`） | 仍留在枚举结果中 |
| 第 3 次 | `83888`、`83889`、`83890`（新增 `83890`） | 仍留在枚举结果中 |

同一探针的稳态采样：本进程在无菜单弹出时持有 **0** 个菜单层窗口（当时唯一的菜单层窗口属其它应用）。

由此得到两条事实：

1. 本进程的菜单窗口确实落在菜单层、owner 即本进程 ⇒ 决议 4 的第三条会在「非菜单栏宿主」之外再一次把自家状态项的唯一响应信号抹掉；
2. 每次弹出产生**新的 `windowID`**，且关闭后窗口仍留在 `CGWindowListCopyWindowInfo(.optionAll)` 的结果里 ⇒ **基线差分**是可靠判据，既不存在「复用旧窗口导致漏判」，也不会把历史菜单窗口误判成本次响应。

### 决议

1. **响应判据改为「投递前基线中不存在、投递后在 `kCGPopUpMenuWindowLevel` 出现的窗口」，owner 只排除菜单栏宿主，不再排除本进程。**
2. `MenuBarItemClicker.awaitMenuResponse(baseline:hostPID:)` 的**签名与「排除菜单栏宿主」条款保持不变**；本次只删除 `ownerPID != getpid()` 一项。
3. 判据不引入任何猜测性分支：**不因目标项归属本进程就跳过判定或直接返回 `.success`**，仍以窗口层事实为准。
4. 明确保留 ADR 0011 决议 4 的**代价声明**：把辅助点击实现为无窗口即时动作的应用，仍会被判 `noResponse` 并触发 Shake。

### 理由与权衡

**为何旧条款是缺陷而非取舍**：拆开旧判据的三条合取看各自的作用域 —— 「新的菜单层窗口」负责层级过滤，已剔除菜单栏项自身的布局扰动（`kCGStatusWindowLevel`）与自有视口（`.screenSaver`）；「owner 非菜单栏宿主」保留；而「owner 非本进程」在两者之上**没有新增任何可剔的噪声**，只能剔除自家状态项的合法响应。它不是「用精度换稳定」，而是纯粹的**信号丢失**。

**为何不顺手把「owner 非菜单栏宿主」一并删除**：该条款的作用域是**宿主代管的系统项**（时钟 / 电池 / Wi-Fi / 声音 / 控制中心等），若它们的菜单也由宿主进程弹出，同样会被这条抹掉。但本机**尚未取证系统项是否响应辅助点击**：2026-09-15 的对照测试把时钟项判为 `noResponse` 时，测试代码本身就带着这条过滤，**无法区分「菜单没弹」与「菜单弹了但被过滤」**。在取得该证据之前不擅自放宽，是刻意遵守 ADR 0010 留下的教训 —— 穷尽性声明必须由矩阵覆盖度支撑，不能由样本数支撑。

**代价**：无新增代价。判据只是少丢一个真实信号。

### 影响

- 修正 [ADR 0011](0011-secondary-click-session-event-routing.md) 决议 4 的 owner 过滤子句；0011 正文按 ADR 规范保持原样不改写，其顶部状态横幅已更新；
- 相关实现见 `MenuBarItemClicker.awaitMenuResponse(baseline:hostPID:)` 与 `Bridging.popUpMenuWindowOwners()`；
- 归入 Issue #55（v0.0.10）的辅助点击交互缺陷修复；
- **待取证（未决）**：宿主代管的系统项（时钟 / 电池 / Wi-Fi / 声音 / 控制中心）在辅助点击下是否弹出**宿主所有**的菜单。若弹出，则「owner 非菜单栏宿主」同样是信号丢失，须另立 ADR 修正。

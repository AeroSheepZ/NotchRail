# 0013. 按屏独立取图：废除跨屏图元共享层（修正 ADR 0004 的取图路径）

> **状态：现行（部分被 ADR 0017 修正）** —— 本 ADR 废除「全局应用图元注册表」与「跨窗口持久缓存」作为**跨屏供图来源**的地位，并修正 [ADR 0004](0004-zero-fallback-real-bitmap-mirroring.md) 确立的**逐窗截图**取图路径。本 ADR 决议 1 与 4 中关于「非活动屏无需移交焦点即可通过区域级合成独立自采位图并原位派发点击」的前提与假设已被 [ADR 0017](0017-active-menubar-monopoly-and-focus-handoff.md) 证伪并取代；废除跨屏共享层、图元键包含 `displayID` 的决议继续有效。
>
> **实现状态：已落地（v0.0.11）** —— 决议已全面落地闭环。图元缓存键绑定 displayID，废除全局应用图元注册表与跨屏供图，结合 ADR 0017 的 Focus Handoff 实现按屏独立自治。

### 背景

v0.0.10 期间排查三个表象缺陷 —— ① 非激活屏状态项图标捕获不到；② 强行改用缓存图标后仍部分丢失；③ 强行在非激活屏显示并派发菜单栏点击无效。此前的处置建立在一条**从未取证的假设**上：「WindowServer 在非聚焦屏幕上为节能暂停菜单项光栅化，窗口截图返回全透明」，于是补丁方向一直是**跨屏供图**（全局应用图元注册表 + 跨窗口持久缓存 + 多层 `??` 回退）与**分辨率保护**（`storeKeepingHighestResolution`）。

本机实测（macOS 26，双屏：内建刘海屏 2x + 外接平直屏 1x）**推翻该假设**。四组探针：

**探针一 · 窗口元数据枚举（无需任何授权）**

两屏各持有一套**几何等价**的状态项窗口。菜单栏状态项部署跨度两屏同为 794pt，项宽序列逐项吻合（15 项对 15 项），`kCGWindowName` 呈**逐屏互补**：

| 屏 | 该屏是否活动屏 | 实名 bundle id | `Item-0` | 系统项实名 |
| :--- | :--- | :--- | :--- | :--- |
| 内建 | 是 | 0 | 12 | 3 |
| 外接 | 否 | 12 | 0 | 0 |

⇒ 同一批窗口在窗口服务器内走**两条不同的注册路径**；「活动屏被抹去实名、非活动屏保留实名」是稳定的镜像事实。

**探针二 · 屏幕级区域截图**

非活动屏（外接屏）的菜单栏状态项区域**被真实绘制**，图标肉眼与截图均清晰可见，且项数**多于**活动屏 —— 活动屏上被刘海挤占的项（Notion、CodeWhisperer 等）在外接屏正常呈现。

**探针三 · 同一片区域、两种截图 API 对照（同一时刻）**

| 取图方式 | 结果 | 墨迹像素 |
| :--- | :--- | :--- |
| 区域级合成（`.optionOnScreenOnly` + `kCGNullWindowID` + 本屏矩形） | 非活动屏有完整内容 | 26923 |
| 逐窗（`.optionIncludingWindow` + `windowID`） | 非活动屏全透明；活动屏刘海带内项返回 `nil` | 0 |

⇒ **「非活动屏取不到图」是该 API 的读取限制，不是窗口未被绘制。** 这是关键分野：前者是取图路径选错，后者才是平台死界。此前所有结论把两者混为一谈，故补丁永远打在错误的一侧。

**探针四 · 活动权归属（纯枚举判据：活动屏 `Item-0` / 非活动屏实名）**

将窗口只存在于某一块屏的应用置前，两屏的实名 / 匿名分布**整体互换**；再置回原应用，分布**再次互换**。双向、可逆、可重复。

⇒ **活动菜单栏屏由「前台窗口所在屏」决定，且其归属可被程序显式移交。**

### 决议

1. **每块屏的图标必须由本屏自采**，取图路径统一为**区域级合成截图**：以本屏矩形为 `screenBounds`、`.optionOnScreenOnly` + `kCGNullWindowID`，再按本屏各项的真实几何裁剪出单项位图。
2. **禁止任何形式的跨屏图元借用**：全局应用图元注册表、跨窗口持久缓存、以及由两者构成的 `??` 级联回退，一律不得再作为图元来源。图元的唯一来源是**消费它的那一块屏自己采到的结果**。
3. **`iconCacheKey` 必须包含 `displayID`**。以裸 `windowID` 作为稳定键不成立 —— 窗口服务器在状态项集合发生任何增删时，会整体重建内建屏的全部菜单栏项窗口，`windowID` 全量变更，键随即全部失配。这是「图标反复丢失」的直接成因，而非渲染层缺陷。
4. **活动菜单栏屏的判定以「前台窗口所在屏」为准**，禁止以光标所在屏替代。活动权可在屏间移交，移交由**用户的显式动作**（点击该屏的灵动岛）触发，不得由程序猜测式抢焦点。
5. **非活动屏不再承担任何「假装可用」的呈现义务**：其展开态要么呈现本屏真图，要么不呈现，绝不以他屏位图填充、绝不以近似图元占位。
6. **废除为跨屏共享而生的保护性补丁**：`storeKeepingHighestResolution` 的分辨率博弈、面向共享层倍率落差的位图来源诊断，随共享层的废除一并移除。

### 理由与权衡

**为何跨屏共享层必须废除，而不是继续打补丁**：本项目的架构基石是**多屏双轨制**（[ADR 0009](0009-multi-display-panel-registry.md)）—— 每块屏拥有完全独立的数据空间，**杜绝跨屏数据互相污染**。共享图元层是一个**反向的架构决策**：它把「A 屏采到的位图」喂给 B 屏，本质是跨屏数据借用。它的存在使「某块屏的图标是否正确」不再由该屏的事实决定，而由**任意一块屏的历史采集顺序**决定。这正是「发糊」「张冠李戴」「时好时坏」屡修不绝的根源 —— 缺陷不是被引入的，是被架构允许的。

**为何此前会误判为平台死界**：三个探针各自看都对 —— 逐窗截图确实返回全透明（事实），非活动屏确实在 `AXExtrasMenuBar` 中只有退化条目（事实），AX 全表遍历确实拿不到非活动屏的可用坐标（事实）。但「逐窗截图失败」被推论成「窗口没被绘制」，跳过了**换一条取图路径**这一未穷尽的选项。这与 [ADR 0011](0011-secondary-click-session-event-routing.md) 记录的历史教训同源：**组合遗漏不得写成平台死界**。本次补上的是「取图 API 维度」的覆盖。

**代价**：

1. 区域级合成需要**按屏矩形**取图，同一时刻截取 N 块屏即为 N 次合成调用，不再有跨屏「一次采集、多屏复用」的省算力红利。但每屏只在自己需要时采集，稳态下并无额外开销。
2. 单项位图由区域合成后裁剪得到，裁剪精度依赖各项几何的准确性；几何来自窗口扫描，与既有溢出计算同源，不引入新的不确定性。
3. 移交活动权必然伴随前台窗口变化，此为显式代价，须由交互设计承担（见影响项）。

### 影响

- 修正 [ADR 0004](0004-zero-fallback-real-bitmap-mirroring.md) 确立的取图路径；0004 正文按 ADR 规范保持原样不改写，其顶部状态横幅须更新；
- 修正 [ADR 0008](0008-dual-panel-topology.md) 与 [ADR 0009](0009-multi-display-panel-registry.md) 语境下「全局应用图元注册表替代跨屏成对路由」这一过渡性表述的方向；
- 受影响实现：`IconResolver`（三层图元查找、共享层写入、分辨率保护、跨屏来源诊断）、`MenuBarItem.iconCacheKey`（须纳入 `displayID`）、`Bridging`（须提供区域级合成取图）、`MenuBarAXResolver`（全局 AX 条目池的按屏适用边界须显式化）；
- `CONTEXT.md` 中记录「跨屏图元共享注册表」的那个词条随本决议作废，取代概念见该文件新增词条；
- 归入 v0.0.10 的多屏取图与点击可达性修复范畴；
- **未决项**：非活动屏的**点击派发**是否同样可达，尚未取得直接证据。本机外壳无辅助功能权限（合成点击报权限违例），事件合成类实验只能走应用内诊断运行器。在取得证据前，非活动屏不得对外承诺点击可用；交互设计上的兜底路径是「先显式移交活动权，再派发」，该路径的两段（`NSRunningApplication.activate` 移交、会话事件流派发）均已有实证，缺的只是「非活动屏原位派发」这一条的成立与否。
